# Changelog

Все заметные пользовательские изменения проекта публикуются в этом файле.
Формат основан на Keep a Changelog, версии следуют Semantic Versioning.

## [Unreleased]

## [0.0.7] - 2026-10-10

### Added

- Добавлена единая административная дизайн-система с адаптивной боковой
  навигацией, светлой и тёмной темами, доступными состояниями фокуса и мобильными
  таблицами.
- Добавлены отдельные разделы для просмотра долгов и платежей, а также безопасной
  диагностики состояния системы без вывода секретов.
- Добавлены фильтры, сортировка и серверная пагинация для пользователей и журнала
  действий.
- Добавлены новый фирменный знак officium, варианты логотипа и полный набор
  favicon/app-icon.
- Добавлен единый слой человекочитаемых названий полей, ролей, статусов и событий
  с подсказками технических имен для администраторов.

### Changed

- Полностью переработаны обзор, пользователи, профиль пользователя, журнал,
  настройки, справочники, экспорт, вход администратора и обновление сервера.
- Действия с риском потери доступа или данных теперь используют единое явное
  подтверждение.
- Тестовая имперсонализация скрыта и недоступна в production; в development она
  требует явного `TEST_USER_ENABLED=true`.
- Часовой пояс приложения по умолчанию изменён на UTC; существующим установкам,
  которым нужна московская календарная дата, требуется явно задать
  `APP_TIMEZONE=Europe/Moscow`.
- Локальная разработка использует случайный ключ сессии на процесс, если ключ не
  задан; production теперь всегда требует явный ключ.
- Вход через Telegram и Telegram Mini App выключен по умолчанию.

### Security

- Диагностический экран показывает только безопасные сведения о среде, драйвере,
  версии и состоянии функций, не раскрывая строки подключения и секреты.
- Обычному администратору недоступны системные настройки, экспорт, обновление
  сервера и технические детали журнала.

### Known issues

- Раздел «Долги и платежи» (`/admin/finance`) доступен роли `admin` и показывает
  финансовые записи всех пользователей. Раздел будет удалён в следующей версии.

### Upgrade notes

- `OFFICIUM_ENV` по умолчанию равен `production`; для локальной разработки его
  нужно явно задать как `development`.
- Открытый `ADMIN_PASSWORD` больше не поддерживается: аварийный вход принимает
  только `ADMIN_PASSWORD_HASH`.
- Удалены модульный объект `app` (`from app import app`) и CLI-команда
  `copy-mysql-to-sqlite`; приложение создаётся через `create_app()`, точка входа
  — `run:app`.
- `DB_USER` по умолчанию равен `officium` вместо `root`; у
  `SERVER_UPDATE_REPOSITORY` больше нет значения по умолчанию.
- `deploy.sh` перенесён в `scripts/deploy.sh` и требует `--release <tag>` и
  `OFFICIUM_BACKUP_CONFIRMED=true`. Помощник `officium-update-runner` из 0.0.6
  ищет старый путь: после перехода на 0.0.7 переустановите его командой
  `install-officium-updater.sh <service-user>` из обновлённого checkout, иначе
  следующее обновление из админки завершится ошибкой.
- Шаблоны systemd и updater содержат плейсхолдер `<service-user>`, который нужно
  заменить при установке.

## [0.0.6] - 2026-10-09

### Added

- Добавлена страница суперадминистратора для проверки и установки опубликованного релиза.
- Добавлено подтверждение быстрых команд Telegram перед созданием финансовой записи.
- Добавлены понятные страницы ошибок без технических деталей.

### Changed

- Улучшена надёжность создания регулярных расходов, включая повторный запуск и
  восстановление пропущенных месяцев.
- Усилена проверка загружаемых банковских выписок и вводимых сумм, дат и настроек.
- Улучшено отображение дашборда на мобильных устройствах.
- Экспортируемые табличные данные безопасно обрабатывают формульные префиксы.

### Fixed

- Исправлено повторное начисление просроченных процентов при нескольких частичных
  платежах.
- Расчёт процентов теперь корректно учитывает границы календарного года, смену
  ставки и выбранный способ подсчёта дней.
- Платежи больше не принимают некорректные суммы, переплату по закрываемому долгу
  или разбивку, не сходящуюся до копейки.
- Исправлено создание дубликатов регулярных расходов при параллельных запусках.
- Исправлено восстановление аварийной админ-сессии после impersonation.
- Исправлена обработка специальных символов в учётных данных MySQL.
