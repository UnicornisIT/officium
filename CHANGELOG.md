Формат основан на Keep a Changelog, версии следуют Semantic Versioning.

## [0.0.8] - 2026-10-13

### Не проверено перед выпуском

Релиз выпущен решением владельца без staging-проверок из
`docs/RELEASE_CHECKLIST.md`: установка на чистую Ubuntu VM, обновление по кнопке
из админки через новый updater, failure injection и откат, таймер после
перезагрузки, нагрузочный тест, реальный Telegram на iOS/Android. CI проверил
unit/integration на Python 3.10 и 3.13, миграции и дамп/восстановление на MySQL 8,
Playwright в Chromium, Firefox и WebKit и аудит зависимостей.

### Административная панель

- Удалён раздел «Долги и платежи», который показывал роли `admin` финансовые
  записи всех пользователей, и финансовые счётчики в карточке пользователя.
- Экспорт превращён в аудит-выгрузку: `accounts.csv` и `activity_log.csv` без
  финансовых данных; маршруты CSV долгов и платежей удалены.
- Вход от имени пользователя требует причину, по умолчанию работает в режиме
  «только просмотр», ограничен по времени (`impersonation_timeout_minutes`),
  показывает баннер на всех страницах и хранит сеансы в таблице
  `impersonation_sessions`; изменения «от имени» записываются в журнал.
- Журнал действий сохраняет записи удалённых пользователей и подпись автора,
  ищет по пользователю, типу объекта и сеансам входа от имени пользователя.
- Карточка пользователя: раздельные действия, роль через список, удаление в
  «Опасной зоне» с вводом username; `admin` управляет только пользователями.
- Обзор показывает регистрации за 7 и 30 дней, активные сеансы входа от имени
  пользователя и статус обновления сервера; меню разделено на основные разделы
  и группу «Система», недоступные разделы открывают страницу 403.
- Настройки сгруппированы и объясняют, что меняют; `payment_warning_days`,
  `urgent_payment_days` и `archive_enabled` подключены к интерфейсу и боту,
  `default_currency` и `overdue_after_date` удалены.
- Справочники подсказывают продукты, ставки и шаблоны комментариев в форме
  долга, поддерживают переименование и выключение; неиспользуемые типы удалены.
- Новый фирменный знак «Замыкание», favicon и иконки приложения.

### Security

- Выход из аккаунта во время входа от имени пользователя больше не позволяет
  следующему посетителю браузера восстановить сессию суперадминистратора.
- Блокировка аварийного входа хранится на сервере, а не в cookie.
- IP-адрес в журнале берётся из `remote_addr` после разбора доверенного прокси,
  а не из заголовка `X-Forwarded-For`, который задаёт клиент.
- Сообщения админки передаются через flash, а не через `?success=` в URL.

### Upgrade notes

- Новые миграции: `20261012_audit_log`, `20261012_impersonation`,
  `20261012_retire_settings`, `20261012_dictionary_types`. Downgrade последней
  не восстанавливает удалённые элементы справочников, а downgrade
  `20261012_impersonation` оставляет пустую таблицу `impersonation_sessions`.
- Активные сеансы входа от имени пользователя, начатые до обновления,
  завершаются при первом запросе.
- Миграция `20261013_debt_enums` переводит на MySQL колонки `debts.repayment_type`,
  `day_count_convention` и `early_repayment_strategy` из `VARCHAR(24)` в `ENUM`, как
  в модели. Если в них есть недопустимые значения, миграция останавливается и
  называет колонку; исправьте строки и запустите её снова.

- Обновлены Werkzeug до 3.1.9 и pypdf до 6.19.0 для устранения девяти
  уязвимостей, подтверждённых блокирующим `pip-audit`.
- Build-time pip/setuptools закреплены отдельно и обновляются до проверенных
  версий до установки runtime-зависимостей нового релиза.

### Added

- Добавлены управляемый Ubuntu installer, версионированные release-каталоги,
  атомарное переключение `current`, read-only post-deploy smoke и recovery.
- Добавлены socket-activated privileged updater, MySQL backup/restore gate,
  Playwright Chromium/Firefox/WebKit и отдельный staging release gate.
- Добавлена настройка публичных контактов и ссылок через superadmin UI.

### Fixed

- Flask больше не запускает `sudo`; обновление совместимо с
  `NoNewPrivileges=true` и использует credential-checked Unix socket.
- Waitress запускается через `run:app`, а список trusted proxy headers передаётся
  одним systemd-аргументом.
- MySQL dump больше не требует глобальный `PROCESS` для tablespaces.
- Обновление не выполняет checkout поверх активного дерева и не оставляет
  partial release при ошибке зависимостей или миграции.
- Legacy migration устанавливает unit/updater/smoke только из проверенного target
  release и не зависит от executable bit исходных `.sh` файлов.
- Candidate release перед активацией становится root-owned/read-only и повторно
  сверяется с remote tag/commit и tracked Git tree.
- Любая ошибка или timeout после переключения `current` запускает rollback;
  неуспешный restart старой версии получает отдельный recovery status.
- Readiness проверяет реальную доступность SQLite backup API или MySQL schema
  dump без `PROCESS`, прежде чем разрешить обновление.
- Системный экран показывает effective Telegram state с учётом DB и `.env`.
- Удалена неполная настройка private-repository token; текущий updater явно
  поддерживает только публичный GitHub repository.
- Исправлены размеры и выравнивание полей, расположений и переключателя
  публикации в форме контакта на desktop и mobile; выбор иконки теперь показывает
  сам значок, понятное название и техническое имя каждого варианта.
- Исправлено сжатие всей страницы обновления при inline alert, переполнение
  таблицы пользователей на laptop viewport и наложение readiness-статусов.
- Парные панели и поля фильтров теперь имеют симметричную геометрию; иконки
  поиска больше не перекрывают первые буквы введённого текста и placeholder.
- Навигация больше не переносит подписи при browser zoom: до переполнения она
  переключается в компактные кнопки-иконки. Карточка входа больше не обрезает
  dev-действия, а пустые responsive-таблицы не превращаются во вложенные
  перекошенные карточки.

## [0.0.7] - 2026-10-10

### Added

- Добавлена единая административная дизайн-система с адаптивной боковой
  навигацией, светлой и тёмной темами, доступными состояниями фокуса и мобильными
  таблицами.
- Добавлены отдельные разделы для просмотра долгов и платежей, а также безопасной
  диагностики состояния системы без вывода секретов.
- Добавлены фильтры, сортировка и серверная пагинация для пользователей и журнала
  действий.
- Добавлены новый фирменный знак officium, варианты логотипа и полный набор
  favicon/app-icon.
- Добавлен единый слой человекочитаемых названий полей, ролей, статусов и событий
  с подсказками технических имен для администраторов.

### Changed

- Полностью переработаны обзор, пользователи, профиль пользователя, журнал,
  настройки, справочники, экспорт, вход администратора и обновление сервера.
- Действия с риском потери доступа или данных теперь используют единое явное
  подтверждение.
- Тестовая имперсонализация скрыта и недоступна в production; в development она
  требует явного `TEST_USER_ENABLED=true`.
- Часовой пояс приложения по умолчанию изменён на UTC; существующим установкам,
  которым нужна московская календарная дата, требуется явно задать
  `APP_TIMEZONE=Europe/Moscow`.
- Локальная разработка использует случайный ключ сессии на процесс, если ключ не
  задан; production теперь всегда требует явный ключ.
- Вход через Telegram и Telegram Mini App выключен по умолчанию.

### Security

- Диагностический экран показывает только безопасные сведения о среде, драйвере,
  версии и состоянии функций, не раскрывая строки подключения и секреты.
- Обычному администратору недоступны системные настройки, экспорт, обновление
  сервера и технические детали журнала.

### Known issues

- Раздел «Долги и платежи» (`/admin/finance`) доступен роли `admin` и показывает
  финансовые записи всех пользователей. Раздел будет удалён в следующей версии.

### Upgrade notes

- `OFFICIUM_ENV` по умолчанию равен `production`; для локальной разработки его
  нужно явно задать как `development`.
- Открытый `ADMIN_PASSWORD` больше не поддерживается: аварийный вход принимает
  только `ADMIN_PASSWORD_HASH`.
- Удалены модульный объект `app` (`from app import app`) и CLI-команда
  `copy-mysql-to-sqlite`; приложение создаётся через `create_app()`, точка входа
  — `run:app`.
- `DB_USER` по умолчанию равен `officium` вместо `root`; у
  `SERVER_UPDATE_REPOSITORY` больше нет значения по умолчанию.
- `deploy.sh` перенесён в `scripts/deploy.sh` и требует `--release <tag>` и
  `OFFICIUM_BACKUP_CONFIRMED=true`. Помощник `officium-update-runner` из 0.0.6
  ищет старый путь: после перехода на 0.0.7 переустановите его командой
  `install-officium-updater.sh <service-user>` из обновлённого checkout, иначе
  следующее обновление из админки завершится ошибкой.
- Шаблоны systemd и updater содержат плейсхолдер `<service-user>`, который нужно
  заменить при установке.

## [0.0.6] - 2026-10-09

### Added

- Добавлена страница суперадминистратора для проверки и установки опубликованного релиза.
- Добавлено подтверждение быстрых команд Telegram перед созданием финансовой записи.
- Добавлены понятные страницы ошибок без технических деталей.

### Changed

- Улучшена надёжность создания регулярных расходов, включая повторный запуск и
  восстановление пропущенных месяцев.
- Усилена проверка загружаемых банковских выписок и вводимых сумм, дат и настроек.
- Улучшено отображение дашборда на мобильных устройствах.
- Экспортируемые табличные данные безопасно обрабатывают формульные префиксы.

### Fixed

- Исправлено повторное начисление просроченных процентов при нескольких частичных
  платежах.
- Расчёт процентов теперь корректно учитывает границы календарного года, смену
  ставки и выбранный способ подсчёта дней.
- Платежи больше не принимают некорректные суммы, переплату по закрываемому долгу
  или разбивку, не сходящуюся до копейки.
- Исправлено создание дубликатов регулярных расходов при параллельных запусках.
- Исправлено восстановление аварийной админ-сессии после impersonation.
- Исправлена обработка специальных символов в учётных данных MySQL.
