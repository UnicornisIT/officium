# Release v0.0.24-alpha

Ежемесячные расходы получили Telegram-напоминания, а бот — получение команд
через long polling для серверов с недоступным входящим webhook. Установка,
обновление и откат автоматически согласуют службы с сохранённой конфигурацией.

## Уведомления в профиле

- Одна карточка «Уведомления»: сначала ежемесячные расходы, затем автомобили,
  между ними разделитель. Каждый подраздел сохраняется независимо.
- Для ежемесячных расходов доступны включение, местное время, часовой пояс
  и срок до списания. По умолчанию — включено, 10:00, Europe/Moscow, за один день.
- Одно сообщение содержит предстоящие списания и итоговую сумму. Учитываются
  короткие месяцы и границы года; доставка возможна в течение шести часов
  после выбранного времени. Автогенерация расходов работает отдельно.
- Журнал успешной доставки и блокировки защищают от повторного и параллельного
  запуска. Блокировка бота или недоступный чат выключают только ежемесячные
  напоминания пользователя; после восстановления их можно включить в профиле.
- Кнопки открытия бота и проверки сообщения общие для обоих подразделов.
  Тест не включает расписания, повтор доступен раз в минуту.

## Telegram и развёртывание

- `TELEGRAM_RECEIVE_MODE=webhook` остаётся режимом по умолчанию.
  При блокировке входящих подключений Telegram доступен `polling`.
- Необязательные `HTTPS_PROXY` и `NO_PROXY` в `.env.example` закомментированы.
  Уже настроенный `shared/.env` сохраняется при повторной установке,
  обновлении и откате; включённый прокси не комментируется заново.
- `telegram-setup` проверяет бота и применяет режим без удаления ожидающих
  команд. `--dry-run` проверяет конфигурацию без сетевых запросов и изменений.
- Managed-деплой запускает polling только в выбранном режиме, а таймер
  ежемесячных напоминаний — при наличии токена, независимо от команд бота
  и автомобильных уведомлений. Интервал проверки расписания — пять минут.
- Службы синхронизируются при обновлении и откате, включая первый переход
  со старого updater. Используются пути и пользователь конкретной установки.

## Обновление

1. Сохраните резервную копию БД и `shared/.env`.
2. Примените `flask --app run.py db upgrade` до запуска нового кода.
   Миграция `20261124_monthly_reminders` добавляет расписание и журнал доставки,
   сохраняет существующие расходы и исправляет старый внешний ключ
   `expenses.generated_from_id` до ожидаемого `ON DELETE SET NULL`, если требуется.
3. При managed-обновлении службы настраиваются автоматически. Для ручной
   установки используйте [инструкцию развёртывания](../DEPLOYMENT.md#telegram-через-прокси-polling-и-ежемесячные-напоминания).
4. Проверьте `telegram-diagnostics --network`, состояние служб и
   `send-monthly-expense-reminders --dry-run`. В режиме polling отсутствие
   зарегистрированного webhook ожидаемо. Реальную отправку из профиля
   выполняйте отдельно по явному нажатию.

Не запускайте два poller на один токен или одновременно timer и cron одной
задачи. Прокси обеспечивает исходящий доступ и не исправляет входящий webhook.
Откат кода не откатывает схему БД автоматически.

## Документация и проверки

Обновлены встроенное руководство, 18 иллюстраций на вымышленных данных,
README на русском и английском, инструкции профиля, расходов и развёртывания.

Локальные проверки: 1323 теста Python (8 пропусков по платформе), восемь
сценариев профиля в Chromium/WebKit, четыре сценария документации в Chromium,
проверки миграций SQLite и компиляции MySQL DDL. Живые MySQL и systemd
проверяются отдельно в Linux CI; локальные проверки не заменяют проверку
целевого окружения. Рабочий сервер и реальные чаты при подготовке не менялись.

Если Telegram принял сообщение, но подтверждение или коммит журнала потеряны,
повторная отправка остаётся возможной: внешняя доставка и БД не образуют общую
транзакцию. Положительный ответ API подтверждает принятие, а не прочтение.
