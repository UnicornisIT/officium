# Связь расхода с погашением долга

Финансовый план больше не исключает расход категории «Кредиты» по совпадению
суммы или фрагмента названия банка/продукта. Такие совпадения показываются
как возможные дубли, остаются в бюджете и требуют сверки. Поэтому после
обновления обязательные расходы могут вырасти: ранее скрытые суммы становятся
видимыми, а причина отражается в предупреждениях плана.

В форме расхода поле «Погашение долга» явно связывает запись с конкретным
долгом пользователя через nullable `expenses.repayment_debt_id`. Это означает,
что расход повторяет месячный платёж долга в плане. Само связывание не создаёт
`Payment`, не меняет остаток долга и не удаляет историю расходов.

План исключает связанную запись только при точном совпадении суммы до копейки
с месячным платежом активного долга, представленным в плане. По одному долгу
исключается не более одной записи. Расхождения сумм, несколько связанных
расходов и связи с отсутствующими в плане долгами остаются учтёнными с
предупреждением. При изменении графика или закрытии долга нужна повторная
сверка.

Способ оплаты остаётся отдельным полем: покупка кредитной картой сама по себе
не является погашением задолженности. Только расходы категории «Кредиты»
могут получить связь с погашаемым долгом. Новые ежемесячные копии наследуют
явную связь; исторические записи автоматически не связываются. Импорт не
выводит связь из названия, суммы или карты; при обновлении существующей записи
сохраняет уже заданную связь.

Перед развёртыванием выполните тесты `tests/test_expense_repayment_migration.py`:
это dry-run на временной SQLite-БД с проверкой истории и удаления долга, а
также генерация MySQL DDL без подключения к серверу. Миграция
`20261202_expense_repayment` добавляет nullable колонку, индекс и внешний ключ
`ON DELETE SET NULL`, не выполняет backfill и не переписывает суммы.

Для развёртывания примените обычную команду `flask db upgrade` до запуска
обновлённого приложения. SQLite пересоздаёт таблицу расходов через Alembic
batch mode: потребуется место для копии таблицы. Внешние ключи отключаются
в autocommit-блоке только на время пересоздания, затем исходный режим
восстанавливается, чтобы не запускать каскадное удаление зависимой истории.
MySQL/MariaDB выполняют ALTER TABLE, что может
потребовать блокировки таблицы. Используйте штатное резервное копирование.
Откат миграции удаляет явные связи, сохраняя сами расходы. Реальные финансовые
записи при разработке и dry-run не изменяются.

Файлы исправления:

- `app/models.py` — явная ссылка на погашаемый долг.
- `app/services/expense_service.py` — проверка принадлежности долга и категории.
- `app/services/monthly_expenses_service.py` — наследование связи новыми копиями.
- `app/services/financial_plan_service.py` — исключение только подтверждённого
  совпадения, предупреждения при неопределённости.
- `app/routes/expenses.py`, `templates/expenses.html` — выбор долга в форме.
- `app/routes/debts.py` — снятие связей при удалении долга, включая SQLite без FK.
- `templates/financial_plan.html` — отображение возможных дублей.
- `migrations/versions/20261202_expense_repayment_debt.py` — изменение схемы.
- `tests/test_financial_plan.py`, `tests/test_expense_service.py`,
  `tests/test_expense_repayment_migration.py`, `tests/test_migrations.py`,
  `tests/test_vehicle_maintenance_migration.py` —
  регрессии, форма, изоляция пользователей, история и цепочка миграций.
