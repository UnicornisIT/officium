# Этап 0: сравнение экранов расходов

Исходная версия: `origin/master`, коммит
`5fd836b63a830f9d733458a2c8ea3fc18a096a16`.

Playwright: `tests/e2e/expense-service.spec.js`, Chromium, высота viewport 1000px,
ширина 1440px и 390px, светлая и тёмная тема. На ширине 390px используется
заглушка Telegram WebApp и вход `/telegram-app`. Данные вымышленные;
сервер работает с отдельной временной SQLite-базой.

Для каждого сочетания ширины и темы сохранены заполненная форма добавления
(`add-form`) и страница после сохранения (`expenses`). Файлы `before` получены
на исходном master, `after` — после рефакторинга. Все восемь пар PNG совпали
побайтно. Шаблоны, стили и клиентский код приложения не изменялись.

Повторение снимков: задайте `EXPENSE_CAPTURE_DIR` абсолютным путём к общему
каталогу вне `test-results`, затем запустите спек на исходной и новой версии
с `EXPENSE_CAPTURE_PHASE=before` и `EXPENSE_CAPTURE_PHASE=after` соответственно.
При наличии исходного снимка тест проверяет точное совпадение PNG.
Для сравнения используйте один браузер и одинаковую последовательность тестов:

```bash
npx playwright test tests/e2e/expense-service.spec.js --project=chromium --grep 'preserves'
```

Остальные два сценария спека проверяют создание, изменение и удаление обычного
и ежемесячного расхода через веб и приватность журнала администратора.
