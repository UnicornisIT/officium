# Сбой WebKit после слияния этапа 1

Исходный CI: https://github.com/UnicornisIT/officium/actions/runs/40657058490.
Коммит master: `1713552d8b1b83bbac2d53a3ca7e840acc22f19f`.

## Причина

В первичной попытке `vehicles-checklist.spec.js` после нажатия
«Восстановить автомобиль» немедленно выполнялся `page.goto(editExpense)`.
Сетевая трассировка содержит ожидаемые 404 проверки чужих идентификаторов,
но не содержит успешного POST восстановления владельца после возвращения
в его сессию. Снимок последующего редактирования расхода показывает
«Автомобиль в архиве: нельзя менять автомобиль и сумму расхода до
восстановления». WebKit не успел отправить отложенную навигацию формы:
следующий переход теста прервал восстановление.

Повторная попытка использовала те же имена автомобилей из оставшейся базы,
поэтому остановилась на создании первой машины из-за дублирования названия.

## Исправление

- До клика зарегистрировано ожидание POST `/vehicles/<id>/restore`.
  Проверяется ответ 302, затем наличие ссылки редактирования в карточке.
  Только после этого открывается расход.
- Названия включают номер повтора и повторного прогона.
- Проверки ожидаемого URL используют обычный лимит утверждения вместо
  ожидания до общего тайм-аута сценария. Ошибки валидации не скрываются.

Правила архива и расходы приложения не изменены. Исправление оформлено
отдельно от уже слитого этапа 1.

## Проверено

Исправленный сценарий WebKit выполнен два раза подряд на одной
одноразовой базе: `2 passed (4.4m)`, без повторных попыток после ошибок.
Команда: `playwright test tests/e2e/vehicles-checklist.spec.js --project=webkit --grep cashflow --retries=1 --repeat-each=2`.
Полный CI нового PR должен подтвердить остальные браузеры отдельно.
