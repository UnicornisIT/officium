SVG кузовов и флагов нарисованы специально для проекта без сторонних
библиотек, изображений и CDN. Права на новые SVG предоставляются на тех же
условиях, что и на исходный код проекта. Флаги — компактные схематичные
изображения; AB — собственный код справочника, не ISO 3166. При отсутствии
флага выводится код страны.

Детальные SVG воспроизводятся командой `python scripts/build_vehicle_illustrations.py`.
Кузов использует `currentColor`, а нейтральные материалы и полупрозрачные
блики сохраняют свои цвета. В форме есть живой предпросмотр кузова и цвета.
Предпросмотр использует сгенерированный детализированный лесной фон
с горизонтальной дорогой; автомобиль остаётся отдельным SVG, а палитра
расположена под сценой. [Файл и промпт генерации](FOREST_BACKGROUND.md).
После добавления фона 2 сценария палитры в Chromium прошли: обе темы,
1440/390 px и сохранение выбранного цвета.
Карточки появляются последовательно и реагируют на наведение, а смена цвета
и открытие палитры сопровождаются короткими переходами. При системном
уменьшении движения эти эффекты отключены; на сенсорном экране нет
реакции карточек на наведение.
Палитра и дополнительные поля тягача/прицепа разворачиваются и сворачиваются
по высоте за 300 мс. Повторное действие меняет направление текущей анимации;
скрывающиеся элементы исключаются из управления клавиатурой. Проверка
`tests/e2e/vehicle-disclosure-motion.spec.js` прошла в Chromium, Firefox
и WebKit, включая Escape и режим уменьшения движения.
Выбор цвета объединён с предпросмотром: «Изменить цвет» открывает 12 готовых
оттенков и свою палитру. Пипетка доступна при поддержке браузером EyeDropper;
в остальных браузерах остаётся стандартная палитра. Escape сворачивает панель.
Сценарии выбора, сохранения и результата API пипетки находятся в
`tests/e2e/vehicle-color-picker.spec.js`; нативный захват цвета с экрана
в автотесте заменён вымышленным результатом API.
Локальная проверка 27.10.2026: 6 из 6 сценариев прошли в Chromium, Firefox
и WebKit; проверены 1440/390 px, обе темы, готовые и свои цвета,
сворачивание панели, отсутствие переполнения и сохранение при редактировании.
Форма следует согласованному расположению: название на всю ширину,
тип/кузов, топливо/статус, марка/модель, год/VIN, госномер/страна,
напоминание/плательщик; ниже — переключатель служебного авто и миниатюра
с выбором цвета. На узком экране поля идут в одну колонку.
После перестановки повторены 2 сценария палитры в Chromium, оба прошли.
Пояснения VIN, госномера, напоминания о пробеге и плательщика по умолчанию
доступны через стандартный компонент «i» проекта:
наведение, фокус или нажатие открывают текст, Escape закрывает его.
При выборе тягача появляется дополнительная подсказка у «Названия прицепа».
Остальные поля не содержат значков «i» и постоянных пояснений.
`tests/e2e/vehicle-field-hints.spec.js` проверяет подсказки на 1440/390 px,
границы всплывающих окон и отсутствие случайного изменения переключателя.

## Локальный запуск

Запускать из каталога репозитория после установки зависимостей по README.
Используется новая тестовая база, а не существующая `dev.db`.

PowerShell:

```powershell
git fetch origin
git checkout feature/vehicles-stage-1-core
.venv\Scripts\Activate.ps1
$env:OFFICIUM_ENV = 'development'
$env:SECRET_KEY = 'local-vehicles-fictional-data-only-secret'
$env:DATABASE_URL = 'sqlite:///' + ($PWD.Path.Replace('\', '/') + '/instance/vehicles-manual-test.sqlite')
$env:DEV_LOGIN_ENABLED = 'true'
$env:VEHICLES_ENABLED = 'true'
$env:FLASK_DEBUG = 'true'
$env:SESSION_COOKIE_SECURE = 'false'
flask db upgrade
python run.py
```

Bash:

```bash
git fetch origin
git checkout feature/vehicles-stage-1-core
source .venv/bin/activate
export OFFICIUM_ENV=development
export SECRET_KEY=local-vehicles-fictional-data-only-secret
export DATABASE_URL="sqlite:///$PWD/instance/vehicles-manual-test.sqlite"
export DEV_LOGIN_ENABLED=true VEHICLES_ENABLED=true FLASK_DEBUG=true
export SESSION_COOKIE_SECURE=false
flask db upgrade
python run.py
```

Открыть `/dev-login/user`, затем `/vehicles`. Страны настраиваются через
`/dev-login/superadmin` → `/admin/dictionaries` → «Страны учёта автомобилей».

## Принятые решения и ограничения этапа

- Сервис этапа 0 уже находится в базовом `origin/master`. `docs/ROADMAP.md`
  в базе отсутствовал; прочитан отдельный файл ROADMAP.md, присланный владельцем.
- Замер уникален для автомобиля и даты, будущие даты запрещены. Для отсутствия
  замеров напоминание появляется сразу. Для старого замера — строго после
  интервала, snooze истекает в начале указанной даты по APP_TIMEZONE.
- Нельзя архивировать тягач с неархивными прицепами: сначала отвязать или
  архивировать их. Имена сохраняют уникальность и после архивации.
- Ежемесячные копии сохраняют vehicle_id; для архивного авто новые копии
  не генерируются. Удаление привязанного расхода также требует восстановления.
- default_payer хранит настройку. Все создаваемые расходы этого этапа личные;
  отдельное хранение трат организации относится к этапу 2.
- Миграция следует существующему подходу forward-only: downgrade сохраняет
  историю. Перед обновлением требуется обычная резервная копия.
- Настоящий Telegram-клиент и production-развёртывание проверяются отдельно.
  В локальных миграционных тестах выполнены SQLite upgrade с существующим
  расходом и компиляция фактического DDL для MySQL. Проверка настоящей MySQL
  и восстановления резервной копии прошла в CI; подробности в отчёте QA.
