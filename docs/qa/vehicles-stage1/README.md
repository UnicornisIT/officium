## Локальный запуск

Запускать из каталога репозитория после установки зависимостей по README.
Используется новая тестовая база, а не существующая `dev.db`.

PowerShell:

```powershell
git fetch origin
git checkout feature/vehicles-stage-1-core
.venv\Scripts\Activate.ps1
$env:OFFICIUM_ENV = 'development'
$env:SECRET_KEY = 'local-vehicles-fictional-data-only-secret'
$env:DATABASE_URL = 'sqlite:///' + ($PWD.Path.Replace('\', '/') + '/instance/vehicles-manual-test.sqlite')
$env:DEV_LOGIN_ENABLED = 'true'
$env:VEHICLES_ENABLED = 'true'
$env:FLASK_DEBUG = 'true'
$env:SESSION_COOKIE_SECURE = 'false'
flask db upgrade
python run.py
```

Bash:

```bash
git fetch origin
git checkout feature/vehicles-stage-1-core
source .venv/bin/activate
export OFFICIUM_ENV=development
export SECRET_KEY=local-vehicles-fictional-data-only-secret
export DATABASE_URL="sqlite:///$PWD/instance/vehicles-manual-test.sqlite"
export DEV_LOGIN_ENABLED=true VEHICLES_ENABLED=true FLASK_DEBUG=true
export SESSION_COOKIE_SECURE=false
flask db upgrade
python run.py
```

Открыть `/dev-login/user`, затем `/vehicles`. Страны настраиваются через
`/dev-login/superadmin` → `/admin/dictionaries` → «Страны учёта автомобилей».

## Чек-лист ручной проверки

- [ ] В верхней навигации между ипотекой и архивом открыть «Модули» наведением;
  проверить переходы к автомобилям и целям, Escape и управление клавиатурой.
  На узком экране меню открывается нажатием.
- [ ] Добавить легковую с вымышленным номером `a123bc77`: увидеть `А123ВС77`.
- [ ] Ввести `d123bc77`: получить понятный отказ без сохранения автомобиля.
- [ ] Добавить тягач и сразу прицеп; открыть оба и проверить текущую связку.
- [ ] У прицепа не должно быть топлива, вкладки пробега и напоминаний.
- [ ] Добавить через карточку расход; проверить категорию «Транспорт»,
  историю расходов, вкладку авто и сумму месяца на главной.
- [ ] Добавить замеры 100 и 200 км на последовательные даты; попробовать
  99 км после первого и 201 км между ними: оба варианта отклоняются.
- [ ] Открыть главную и список без свежих замеров; обновить несколько авто
  одной формой, затем проверить «Напомнить через 3 дня» и интервал 0.
- [ ] Перевести авто в ремонт: напоминание должно исчезнуть.
- [ ] Заархивировать авто; убедиться, что карточка только для чтения,
  нельзя добавить замер или расход, поменять сумму или авто у связанного
  расхода. Попытаться изменить сумму через импорт ежемесячного расхода.
- [ ] Восстановить авто; повторить изменение расхода.
- [ ] Другой пользователь, включая администратора в личном кабинете,
  должен получать 404 на чужие идентификаторы автомобилей.
- [ ] У суперадминистратора добавить страну без SVG: увидеть код на номере.
  Выключенная страна не предлагается для новых авто; существующая остаётся.
- [ ] В админке и выгрузках журнала нет названий авто, VIN, госномеров,
  сумм пробега и примечаний архива.
- [ ] Проверить ключевые экраны на 1440 и 390 px в обеих темах.
- [ ] В форме выбрать разные кузова и красный, зелёный, белый и чёрный цвета.
  Предпросмотр меняется до сохранения; шины, диски, стёкла и фары сохраняют
  свои материалы. После сохранения выбранный цвет виден в списке и карточке.
- [ ] Перезапустить с `VEHICLES_ENABLED=false`: меню и ссылки на главной
  исчезают, все маршруты модуля возвращают 404.

## Принятые решения и ограничения этапа

- Сервис этапа 0 уже находится в базовом `origin/master`. `docs/ROADMAP.md`
  в базе отсутствовал; прочитан отдельный файл ROADMAP.md, присланный владельцем.
- Замер уникален для автомобиля и даты, будущие даты запрещены. Для отсутствия
  замеров напоминание появляется сразу. Для старого замера — строго после
  интервала, snooze истекает в начале указанной даты по APP_TIMEZONE.
- Нельзя архивировать тягач с неархивными прицепами: сначала отвязать или
  архивировать их. Имена сохраняют уникальность и после архивации.
- Ежемесячные копии сохраняют vehicle_id; для архивного авто новые копии
  не генерируются. Удаление привязанного расхода также требует восстановления.
- default_payer хранит настройку. Все создаваемые расходы этого этапа личные;
  отдельное хранение трат организации относится к этапу 2.
- Миграция следует существующему подходу forward-only: downgrade сохраняет
  историю. Перед обновлением требуется обычная резервная копия.
- Реальная MySQL, настоящий Telegram-клиент и production-развёртывание
  проверяются отдельно. В локальных миграционных тестах выполнены SQLite
  upgrade с существующим расходом и компиляция фактического DDL для MySQL.
