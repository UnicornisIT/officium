## Что проверяют браузерные сценарии

- `tests/e2e/modules-menu.spec.js`: положение меню между ипотекой и архивом,
  разделение пунктов, переходы, наведение и уход мыши, снятие искусственного
  фокуса, Escape, клавиатура и нажатия на узком экране.
- `tests/e2e/vehicles.spec.js`: четыре сочетания ширины 1440/390 px и тем,
  номера РФ и Абхазии, отказ для неверного номера РФ, тягач и прицеп,
  клики по изображению и названию, расход из карточки, скрытый выбор авто
  в обычных расходах, архив, пробег, напоминания и отсутствие горизонтального
  переполнения. Сохраняются 28 снимков ключевых экранов.
- `tests/e2e/vehicles-checklist.spec.js`: влияние расхода на итог месяца,
  монотонность пробега в обе стороны по датам, групповое обновление,
  snooze, интервал 0, ремонт, архив и восстановление, запрет изменения
  суммы и привязки архивного расхода, IDOR с действующим CSRF-токеном,
  страны без флага и отключение страны, приватность админки и CSV журнала,
  запрет изменения архивного ежемесячного расхода импортом настоящего CSV.

## Найдено и исправлено

1. Аудит обнаружил Authlib 1.7.2 с CVE-2026-96760. Зависимость обновлена
   до 1.9.1, добавлен регрессионный тест отклонения пустого массива подписей
   JWS. Это проверка дефекта библиотеки; обход входа в само приложение
   не воспроизводился. [Описание разработчика](https://github.com/authlib/authlib/security/advisories/GHSA-6v38-4h7w-rj9h).
2. Декоративная иконка попадала в доступное название кнопки «Разобрать»
   в импорте выписки. Для неё установлен `aria-hidden="true"`.
3. WebKit теряет фокус без нового `relatedTarget` при клике по пункту меню
   после открытия клавиатурой. Обработчик закрывал меню до перехода.
   Потеря фокуса без нового элемента при наведённом указателе теперь
   сохраняет возможность клика; уход указателя и фокуса наружу закрывают меню.

При разработке нового теста импорта исправлены его вымышленные данные
для распознавания категории «Транспорт» и чтение десятичной точки в сумме.
Защита архивного расхода сработала; сумма осталась прежней. Дополнительная
проверка второго перехода после смены страницы выявила тайм-ауты повторного
наведения Playwright в Firefox и WebKit. Финальный сценарий проверяет
переход к автомобилям указателем, а к целям — клавиатурой; оба режима
открытия, уход мыши и Escape проверяются до первого перехода. Общий бюджет
расширенного сценария с двумя переходами — 120 секунд; ожидания отдельных
утверждений остаются по 8 секунд.

## Воспроизведение

Из активированного окружения с установленными Python- и npm-зависимостями:

```text
python -m unittest discover -s tests -p "test_*.py" -v
node node_modules/@playwright/test/cli.js test tests/e2e/vehicles.spec.js tests/e2e/modules-menu.spec.js tests/e2e/vehicles-checklist.spec.js
python -m pip_audit -r requirements.txt --disable-pip
python -m pip_audit -r requirements-build.txt --disable-pip
```

Снимки экранов и чек-лист находятся в [README](README.md).

## Границы проверки

390 px — браузерная эмуляция с заглушкой Telegram API. Настоящие клиенты
Telegram, вход через реальный Google-аккаунт, физические телефоны и
production-развёртывание не проверялись. Проверки скриптов развёртывания
в CI не означают развёртывание production.

Первый общий локальный прогон остановился на тайм-ауте Firefox с сообщением
SWGL о framebuffer; все 11 сценариев Firefox прошли в отдельных прогонах. В CI первый
браузерный job и его повтор были отменены на установке Playwright и
системных пакетов до запуска тестов. Успешный браузерный CI не заявляется;
локальные проверки учитываются отдельно.
