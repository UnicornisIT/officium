# Оркестровое тестирование этапа 4

Дата: 29–30 октября 2026 года. Проверена ветка feature/vehicles-stage-4-fuel, исходная ревизия c3803fa (PR #11). Повторные проверки выполнялись после исправлений в той же ветке.

Три независимых агента проверяли сервис, безопасность/миграции и браузеры; координатор проверял финансовые отчёты, сводил воспроизведения и исправления. Все данные вымышлены: unit-проверки использовали in-memory SQLite, миграции — временные базы, браузеры — disposable e2e-сервер. Рабочая dev.db не использовалась.

## Подтверждённые дефекты

| Приоритет | Воспроизведение на исходной ревизии | Исправление и повторная проверка |
|---|---|---|
| P1 | SQLite без включённого enforcement FK: удалить личную трату заправки, создать обычную трату с повторно использованным ID. Правка заправки перезаписывала несвязанную трату. Если новая трата принадлежала другому пользователю, смена payer на organization удаляла её. Оба варианта доказаны изолированными тестами, cross-user вариант — запуском исторического record_refueling из c3803fa. | delete_expense явно обнуляет ссылки заправок и обслуживания с синхронизацией ORM. Смена payer использует штатный delete_expense(commit=False), включая проверку владельца. Регрессии подтверждают сохранность несвязанной/чужой траты и финансовой сводки. |
| P2 | Связанную Expense преобразовать в ежемесячную, затем переключить payer self → organization. Прямое удаление оставляло generated_from_id у копий на отсутствующую исходную запись в SQLite. | Штатное удаление очищает ссылки копий и сохраняет аудит. Отдельно проверены commit=False и rollback: ссылки fuel/service, исходная Expense и финансовые представления восстанавливаются. |
| P2 | Ввести 1.005 л × 1.00 ₽: браузер выдавал 1.00 вместо 1.01 из-за двоичной арифметики toFixed. Дополнительная точность исходных полей также расходилась с нормализацией сервера. | Расчёт через масштабированные целые BigInt: HALF_UP для литров до 0.001, цены до 0.01 и произведения до копеек. Проверяются половина копейки, округление полей, десятичная запятая. Версия JS в URL обновлена для сброса старого кэша. |

Исходные падающие проверки сохранены в локальных логах; они не выдаются за успешные прогоны. Историческое cross-user воспроизведение выполнялось в отдельной in-memory базе, без подмены рабочих файлов приложения.

Всего добавлено 30 новых unit-сценариев: 16 сервисных, 11 security и 3 финансовых. Числа в строках таблицы не суммируются: унаследованные базовые проверки повторяются в разных классах.

Сервисные проверки охватывают перенос/снятие пробега, shared manual/service readings, обе смены payer, сбой после удаления траты/после аудита, граничные Decimal, пустой период, внешнее редактирование Expense, сохранность чужих финансов. Security-проверки охватывают CSRF, IDOR, флаг, архив, прицеп, XSS, приватность аудита, ограничения БД, SET NULL и удаление аккаунта с включёнными FK.

Базовая браузерная матрица: Chromium/Firefox/WebKit × 390/1440 px × light/dark. Дополнительно в каждом браузере проверяются 5 примеров округления и цепочка checkbox → ручной итог с допуском → редактирование даты/пробега/payer → период → превышение допуска → архив → прицеп. Расход проверяется в конкретной колонке таблицы; прежнее совпадение текста где-либо в таблице усилено.

## Воспроизводимость

- Unit: .venv/Scripts/python.exe -m unittest discover -s tests -p 'test_vehicle_fuel*.py' -q
- Новые browser cases: node node_modules/@playwright/test/cli.js test tests/e2e/vehicle-fuel-orchestrated.spec.js --workers=1 --reporter=line --output=.tmp/orchestrated-browser-results
- Для свежей baseline-матрицы использована временная копия исходного spec с выводом PNG в .tmp/qa-stage4-orchestrated. Исходные 48 PNG не перезаписывались. После прогона временная копия удаляется.
- SDK Telegram подменён пустым ответом; видеозапись отключена, скриншоты и трассировки доступны. Временный config увеличивал только ожидание запуска e2e-сервера до 180 секунд: при параллельном запуске независимых проверок штатных 60 секунд оказалось недостаточно.

Основные локальные логи: .tmp/orchestrated-fuel-adversarial-fixed.txt, .tmp/orchestrated-fuel-security-final.txt, .tmp/orchestrated-fuel-cross-owner-historical.txt, .tmp/orchestrated-fuel-cross-owner-final.txt, .tmp/orchestrated-fuel-migrations.txt, .tmp/orchestrated-fuel-integration-final.txt, .tmp/orchestrated-fuel-all-final.txt, .tmp/orchestrated-browser.txt.

## Ограничения

MySQL проверен компиляцией DDL, без живого MySQL-сервера. Политика продолжения monthly-групп после ручного изменения связанной Expense не менялась: исправлена целостность ссылок. Сравнение автомобилей и другие функции за пределами исходного ТЗ этапа 4 не добавлялись.
