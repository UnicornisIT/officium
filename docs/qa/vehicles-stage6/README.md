# Этап 6: Telegram-напоминания

> Исторический отчёт этапа. Актуальное описание интерфейса и новые иллюстрации:
> [руководство пользователя](../../USER_GUIDE.md).

Реализованы ежедневная сводка по пробегу, обслуживание по автомобилям,
документы по отдельности. Команд ввода нет. Плашка дашборда не добавлялась.

## Запуск

После обновления «Профиль и личные настройки» актуальные инструкции —
в [DEPLOYMENT.md](../../DEPLOYMENT.md): переустановите таймер на проверку
каждые 5 минут; час и пояс ниже служат значениями по умолчанию до личного
выбора в профиле. Проверка дублей остаётся ежедневной по местной дате пользователя.

После миграции `flask db upgrade` задайте в shared/.env:

```dotenv
VEHICLES_ENABLED=true
VEHICLE_NOTIFICATIONS_ENABLED=true
VEHICLE_NOTIFICATIONS_HOUR=10
VEHICLE_NOTIFICATIONS_BASE_URL=https://your-domain.example
APP_TIMEZONE=Europe/Moscow
TELEGRAM_BOT_TOKEN=<токен>
```

Базовый URL иначе берётся из OFFICIUM_PUBLIC_URL. Настройка по умолчанию
выключена, существующим пользователям предпочтение включается миграцией.
`flask send-vehicle-notifications` выполняет пакетную отправку; альтернативно
POST /internal/vehicle-notifications/run (только peer 127.0.0.1).
В reverse proxy запретите внешний доступ к /internal/ (например,
`location /internal/ { deny all; }`), не переписывайте WSGI REMOTE_ADDR
из непроверенных заголовков.

Таймер использует CLI по образцу monthly-expenses, не требует HTTP-сервера.
Установка после основного installer:

```bash
sudo env VEHICLE_NOTIFICATIONS_ENABLED=true VEHICLE_NOTIFICATIONS_HOUR=10 APP_TIMEZONE=Europe/Moscow bash deployment/install-vehicle-notifications.sh
systemctl list-timers officium-vehicle-notifications.timer
```

APP_ROOT, APP_USER, APP_GROUP, VENV_DIR должны совпадать с основной установкой.
Параметры часа и зоны передайте установщику такими же, как в .env; после
изменения переустановите таймер. Persistent=true догоняет пропущенный запуск.
Для включения и выключения отправки используйте общий переключатель в настройках
супер-администратора. Установщик сохраняет таймер активным независимо от переключателя.
CLI также проверяет сохранённую настройку при каждом запуске.

## Семантика

Хэш документа включает ID документа: kind|vehicle_id|document_id|local_date.
Для остальных типов: kind|vehicle_id|local_date (None для сводки).
Резервирование с unique constraint коммитится перед Telegram API. Ошибка
или авария между резервированием и отправкой не вызывает повтор в тот же
день; следующий день допускает новую попытку. Это гарантия не более одной
попытки в день, а не гарантированной доставки. Смена дня во всём сборе
использует одно значение now в APP_TIMEZONE.

Обслуживание перечисляет только активные позиции soon/overdue. Если общий
technical_condition повышен только документами, пустое сообщение об
обслуживании не отправляется. Документы: включительно 0–14 дней.

## Локальная проверка без ручного прохода

```powershell
.venv/Scripts/python.exe scripts/check_vehicle_notifications.py
```

Нужны установленные зависимости Python, Node.js, пакет Playwright из
package.json и Chromium (`npx playwright install chromium`). Скрипт добавляет
текущий Python в PATH для тестового сервера. Изолированные временные БД и
вымышленный пользователь; рабочая база приложения не используется.
Для проверки только Python: добавьте `--skip-browser`.

- Реальный Telegram-адаптер проверяется до HTTP-границы: успешный запрос,
  ответ ok=false, тайм-аут, приватность логов и отсутствие дублей.
  HTTP полностью подменён, токен вымышленный, отправки в Telegram нет.
- Chromium проверяет профиль в четырёх сочетаниях размера и темы;
  скриншоты: profile-chromium-{390,1440}-{light,dark}.png в этой папке.
- На Linux автоматически проверяются отрендеренные юниты через
  systemd-analyze verify и календарное выражение. Тест также подхватывается
  существующим Linux CI. На Windows он явно пропускается.
- Подтверждение доставки настоящим Telegram и срабатывания Persistent
  настоящим systemd требует соответствующей среды; offline-тесты не
  утверждают, что это проверено.

Результат локального запуска 2026-11-01: 10 Python-проверок успешно,
1 systemd-проверка явно пропущена на Windows; 4 Chromium E2E успешно.
Скриншоты профиля приложены. Скриншот 390/dark просмотрен визуально.

## Исправление браузерной регрессии

CI обнаружил два устаревших селектора «Напомнить через 3 дня» после
перехода к настраиваемому snooze. В vehicles.spec.js и
vehicles-checklist.spec.js проверяются значение срока 3 дня, новая кнопка
«Напомнить позже» и скрытие напоминания после отправки.

1440/390 px, светлая/тёмная темы. Полный CI запускается на новом коммите.
